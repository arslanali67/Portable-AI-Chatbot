# Taste — Architecture & Coding Style

- Prefers clean layered architecture with inward-only dependencies: api (routers) → services → repositories → models; Pydantic schemas are DTO boundaries and ORM models are never exposed directly. Confidence: 0.9
- Prefers async SQLAlchemy 2.x in typed/declarative style (`Mapped[...]` / `mapped_column`) with asyncpg; exactly one central engine and one session factory; sessions come only via `get_db()` dependency injection. Confidence: 0.9
- Multi-tenancy is mandatory and enforced at the repository layer: every query scoped by `organization_id`, no unsafe global `get_by_id`, membership is always verified, and client-supplied IDs are never trusted. Confidence: 0.9
- Prefers extensible string IDs plus registries over enums for providers/models — no branching on provider IDs, new models/providers are pure additions. Confidence: 0.8
- Request schemas are strict: `extra="forbid"`, the server owns ids/roles/sequence numbers, and immutable fields (id, organization_id, timestamps, message role/sequence) cannot be patched by clients. Confidence: 0.8
- Security posture: bcrypt used directly (passlib avoided — incompatible with bcrypt 5.x), JWTs carry only a user id and the user is always reloaded from the DB (token alone grants nothing), and generic 401s avoid user enumeration. Confidence: 0.8
- Defaults and configuration live in one registry/config place (e.g. app/ai/registry.py), never hardcoded in services, routes, or the gateway. Confidence: 0.7
- External integrations (AI providers, HTTP clients) sit behind adapters that translate SDK/HTTP errors into a provider-neutral error hierarchy; raw SDK exceptions, credentials, and internals never escape to the API layer, and responses are normalized to internal DTOs. Confidence: 0.7
- Prefers RESTRICT (non-cascading) foreign keys on history/child tables so dependent data cannot be destroyed accidentally by deleting parent rows; hard deletes are only allowed when no dependent data exists. Confidence: 0.5
- Security is designed in per feature, not bolted on: outbound fetches are SSRF-hardened (scheme/port/credential checks, hostname resolution with every resolved IP validated, each redirect re-validated, fail-closed robots.txt), untrusted retrieved content is delimited and can never override the system prompt, management DTOs exclude credential-bearing fields (e.g. base_url), and errors never expose stack traces, keys, provider internals, or DB details. Confidence: 0.8
- New features define explicit failure semantics and fail closed: documents never become "ready" without valid chunks/vectors (failures marked "failed" and never searchable), a failed AI turn keeps the committed user message but never fabricates an assistant message, empty retrieval adds no fake context, and mid-stream failures emit safe generic errors. Confidence: 0.7
- External work (AI gateway calls, HTTP fetches, streaming) happens outside DB transactions: the user message is committed before the provider call and the assistant message only after success; streaming persists one final assembled message, never token chunks. Confidence: 0.7
- Prefers reuse over new infrastructure: existing columns/pipelines/abstractions are reused (e.g. source_uri for URL ingestion, shared ingestion pipeline) to avoid unnecessary migrations and new dependencies; test-only packages (e.g. fpdf2) are kept out of requirements. Confidence: 0.6
- Keeps each milestone minimal and defers out-of-scope work behind documented seams: no premature platform-admin roles, no mutation endpoints for future systems, no DB tables before they are needed. Confidence: 0.6
